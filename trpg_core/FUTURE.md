# trpg_core — エンジン拡張候補（FUTURE）

決定論エンジン（LLM 不使用・自由度0）を触っていて判明した「今のエンジンでは表現できない
シナリオ表現」の記録。**どちらも Step 3（GM を LLM に置き換える）より後の拡張候補。今は実装しない。**
本編（story/）・canon/ には一切関係しない。ここは trpg_core（エンジン）の設計メモ。

判明した経緯: vT.4-scenarios（テスト用シナリオ群 goblin / thief / beasts / ruins / envoy）を
既存の effect タイプ（hit_bonus / damage_bonus / item / recon）だけで組む過程で、
以下2点が「既存の仕組みで表現できない」と分かった（当時はスコープ外として作らず、指摘に留めた）。

---

## 1. `check_bonus` — 技能判定を stat 指定で +N する effect.type

### 何が足りないか
現状、技能判定（`rules._resolve_check` 相当＝ノードの choice.check）を有利化できる effect は
**`recon` 一本だけ**（`recon_auto` で自動成功 / `recon_bonus` で +N）。
`hit_bonus` / `damage_bonus` は **戦闘の命中・ダメージにしか効かない**（判定には効かない）。

そのため「知識・証拠・人脈が **判定そのもの** を有利化する」表現ができない。具体例:
- ruins（探索）: 「古文書を読む＝知識で mag 判定が楽になる」を出したかったが、
  hit_bonus は判定に効かないため、知識(lore)は**番人戦の命中ボーナス**に流用した。
- envoy（交渉）: 「証拠を集める／顔役に根回しする」の両方で説得判定を有利化したかったが、
  判定に効くのは recon のみ、しかも recon は**単一フラグ**（`has_recon`）なので
  「rapport（人脈）」と「evidence（証拠）」を機構上区別できない。両方まとめて recon 一本で代替した。

### 拡張案（実装イメージ・今は入れない）
`effect: {type: check_bonus, stat: mag, value: 2}`（あるいは `tag`/`check_tag` 指定で
特定判定だけに効く形）を追加し、`_resolve_check` の modifier 計算に
「その stat（またはその tag）に一致する check_bonus を合算」を足す。
`rules` 側に `effect_check_bonus(state, stat, tag)` を新設し、`recon_bonus` と同じ位置で加算する。
- これで「知識→mag判定+2」「証拠→特定の説得判定+2」等が **宣言(YAML)だけ**で書ける。
- recon（auto/bonus）は「罠回避・初撃必中」の別軸として残す（役割が違う）。
- 影響: 既存シナリオは check_bonus を持たないので挙動不変（seed=7 回帰は保たれる想定）。
  ただしエンジン（rules / scenario_loader）に手を入れる変更なので、回帰の再確認が要る。

## 2. `clock` / 難易度逓増 — 時間制限・追跡シナリオ用の状況カウンタ

### 何が足りないか
「**選択のたびに状況が悪化する**」「時間制限」「追跡（無駄足を踏むほど不利）」を表現する、
**累積する状況カウンタ（時計）が無い**。現状:
- ノードは互いに独立で、判定目標は YAML 固定。経過ターン（`state.turn`）に応じて
  判定を難化させる／遭遇を強化する機構が無い。
- 分岐で「無駄足→強い遭遇ノードへ」と *擬似的に* 段差は作れるが、
  「時間が押すほど連続的に不利」という**圧の逓増**は書けない。

これがカテゴリD（`pursuit`「攫われた者を追う」）を今回**作らなかった**理由。

### 拡張案（実装イメージ・今は入れない）
- `state` に `clock`（初期0、増えるほど不利）を持たせる。ノードやアクションに
  `clock_cost:` を宣言し、選択のたびに加算する。
- 判定側で `check` に `clock_scaling:` を宣言し、`_resolve_check` の実効目標を
  `target + f(clock)` と難化させる（または敵の atk/hp を clock で強化する遭遇修飾）。
- エンディング条件に「clock がしきい値を超えたら手遅れ（bad end）」を追加できるようにする。
- 影響: `clock` を宣言しないシナリオは clock=0 のまま無影響（既存挙動不変の想定）。
  これも rules / session / scenario_loader にまたがる変更なので、回帰の再確認が要る。
- 乱数規律の注意: clock による難化は**判定式の変更**なので、seed 再現性（乱数消費順）を
  崩さないよう、clock 加算は乱数を消費しない純粋な状態更新に限る。

---

### 位置づけ
- 両方とも **Step 3（LLM-GM）より後**の検討事項。Step 3 は描写だけを LLM に置き換え、
  判定・数値・進行は不変に保つ設計（`replay.py` の mode=state で保証）なので、
  これらのエンジン拡張は Step 3 と独立に、後から入れられる。
- 実装時は必ず: seed=7 ゴブリン回帰（55 events）と全フィクスチャの replay 完全一致を維持し、
  「宣言しないシナリオは挙動不変」を保つこと。
